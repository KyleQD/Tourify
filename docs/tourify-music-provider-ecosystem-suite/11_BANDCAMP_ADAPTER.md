# 11 — Bandcamp Provider Adapter

## Product model

Bandcamp is not implemented as a general raw-stream provider. It is modeled as:

1. **Official embedded playback** for user-supplied track/album embeds.
2. **Direct-support commerce** through canonical purchase, merch, subscription, and artist links.
3. **Optional partner API integration** only after Bandcamp grants Tourify or participating labels appropriate access.

## V1 workflows

### Add release by URL/embed

- Artist pastes a Bandcamp track or album URL or the embed code generated by Bandcamp.
- Server validates hostname, protocol, allowed iframe source, dimensions, and permitted parameters.
- System extracts only safe identifiers/configuration from user-provided input.
- User reviews artwork/title/artist fields and can correct metadata manually when official machine-readable data is unavailable.
- Store canonical URL and sanitized embed configuration.

### Display and playback

- Render a responsive official iframe.
- Maintain a Tourify shell for queue context and source attribution.
- Do not promise precise seek/progress events unless an official interface supports them.
- Ensure another runtime is stopped before the Bandcamp embed becomes active.

### Commerce

- `Support Artist`, `Buy Digital`, `Buy Vinyl`, `Buy CD`, `View Merch`, or `Subscribe` actions route to canonical Bandcamp URLs.
- Record outbound click attribution only; do not claim purchase completion without an approved API or user-confirmed flow.
- Marketplace cards clearly state checkout occurs on Bandcamp.

## Approved API future scope

Bandcamp documents account, sales-report, and merchandise-order APIs for labels and fulfillment partners who receive access. If access is granted:

- Store credentials per approved user/account.
- Add server-only adapter modules.
- Import sales/order summaries into separate integration tables.
- Never broaden partner credentials to unauthorized artists.
- Add data retention, reconciliation, and support workflows.

## Security

- Strict iframe CSP/frame allowlist.
- Sanitize embed configuration; never store arbitrary HTML.
- Prevent javascript/data URLs.
- No server-side page scraping.
- No hidden audio URL extraction.
- No autoplay.

## Acceptance criteria

- Only official Bandcamp embed origins and safe parameters render.
- Malformed or non-Bandcamp URLs are rejected.
- Bandcamp queue items do not cause overlapping audio.
- Commerce links are accurate and clearly external.
- The feature remains useful without Bandcamp API credentials.

## Cross-cutting implementation guardrails

- **Audit first:** all file targets in this suite are candidates until confirmed against the live Tourify repository.
- **Additive only:** do not reset Supabase; do not drop, rename, truncate, or repurpose production columns or tables.
- **Preserve native playback:** Tourify-hosted audio remains a first-class provider and the fallback path.
- **Normalize at the boundary:** provider payloads are mapped into Tourify domain contracts before entering UI, queue, analytics, or persistence layers.
- **Resolve playback just in time:** expiring or provider-controlled playback URLs are never stored in Supabase, local storage, analytics, logs, or durable queues.
- **Feature-flag every provider:** discovery, connection, import, display, playback, sync, and commerce can be disabled independently.
- **Provider terms override product preference:** the common Tourify UX must adapt to each provider's permitted playback and attribution model.
- **No scraping:** do not scrape Bandcamp or SoundCloud pages, extract hidden stream URLs, bypass embeds, or reverse engineer provider controls.
- **Acting-account authorization:** all mutations must use Tourify's existing account/organization/artist authorization helpers.
- **Idempotency:** imports, links, syncs, analytics milestones, and webhook processing must be safe to retry.
- **Observability without leakage:** log request IDs, provider, operation, latency, and normalized error code; redact tokens, personal data, and playback URLs.
- **Rollback without data loss:** disable flags and detach provider execution paths; retain additive data for later recovery unless a user requests deletion.
