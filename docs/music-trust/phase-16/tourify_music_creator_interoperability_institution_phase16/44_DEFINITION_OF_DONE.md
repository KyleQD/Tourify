# Phase 16 — Definition of Done

Phase 16 is not complete because documents, schemas or UI prototypes exist. Completion is evidence-based.

## Task completion

A task may be `complete` only when its execution-plan entry contains:

1. exact files changed and deployed objects;
2. governing policy, schema, jurisdiction and legal/institutional decision;
3. source manifest and actor authority;
4. commands run and results;
5. unit, integration, RLS, route, worker, reconciliation and regression evidence;
6. security, privacy, accessibility, competition and public-law review where applicable;
7. operational owner, monitor, alert and response target;
8. rollback or compensating action; and
9. explicit unresolved blockers, if any.

## Stage completion

A stage requires completed tasks, independent review, no unresolved critical blocker, tested stop conditions and a signed stage decision.

## Release completion

A release additionally requires:

- an audited repository and deployed-schema map;
- effective source records for the exact activated scope;
- default-deny RLS and API authorization;
- two independent implementations and operators for critical public services;
- successful provider-replacement and Tourify-unavailable drills;
- approved funding, procurement, staffing and oversight;
- public legal-character and service-status disclosures;
- complete existing-system regressions;
- a time-limited activation decision, sunset date and rollback plan.

## Never sufficient

The following are never completion evidence by themselves: a draft instrument, a credential, a legal-status badge, a feature flag, a mock API response, a screenshot, an unchecked migration, an unverified AI summary, a TODO, or an assertion that an external body will approve the work later.
