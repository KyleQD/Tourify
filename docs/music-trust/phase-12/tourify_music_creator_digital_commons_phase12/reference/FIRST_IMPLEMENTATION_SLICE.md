# First Implementation Slice

The first Phase 12 code release should not transfer assets or activate public critical infrastructure.

## Build only

1. Readiness and source-of-truth audit.
2. Critical asset inventory with restricted evidence and a minimal public projection.
3. Separate steward-entity readiness records.
4. Protocol profile and change-proposal records in sandbox state.
5. Operator application and conformance records in sandbox state.
6. Explicit commons participation separate from Tourify accounts.
7. Transition-escrow checklist and Tourify-exit drill planner.
8. Admin review queues and append-only audit/outbox events.

## Do not build yet

- irreversible asset transfer;
- production public identifiers;
- global mandates or collective action;
- public raw-table access;
- production trust roots;
- tokenized identity or membership;
- automatic rights or legal conclusions.

## Required proof

- additive migration and RLS tests;
- no changes to existing music upload, playback or entitlement flows;
- ordinary Tourify account does not create commons participation;
- public asset projection excludes secrets and unverified ownership claims;
- all feature flags default off;
- every action is versioned, idempotent and reversible or compensable.
