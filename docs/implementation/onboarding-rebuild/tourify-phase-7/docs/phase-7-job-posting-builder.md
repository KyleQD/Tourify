# Phase 7 — Universal Job Posting Builder

## Purpose

Phase 7 replaces the venue-only admin job posting form with a reusable `HiringEntity`-scoped job posting builder. It writes real data through the Phase 4 `/api/hiring/job-postings` endpoint and keeps application form fields typed instead of using `z.any()`.

## Files

```txt
types/job-posting-builder.ts
lib/hiring/job-posting-builder-schema.ts
components/hiring/job-posting-array-field.tsx
components/hiring/application-form-field-builder.tsx
components/hiring/job-posting-builder.tsx
app/actions/hiring/create-job-posting.ts
app/admin/dashboard/jobs/new/page.tsx
```

## What this phase changes

- Adds typed application form field definitions.
- Adds `JobPostingBuilder` for Venue, Organization, and Artist employers.
- Adds a real route mount at `/admin/dashboard/jobs/new` that reads `entity_type` and `entity_id` search params.
- Adds a server action adapter that delegates to `HiringOnboardingService.createJobPosting()`.
- Uses `/api/hiring/job-postings` from Phase 4 for the client submit path.

## What this phase does not change

- It does not create staff members.
- It does not approve applications.
- It does not run onboarding.
- It does not upload documents.
- It does not use mock jobs, mock templates, or fake application data.

## Expected query params

The new route supports:

```txt
/admin/dashboard/jobs/new?entity_type=venue&entity_id=<venue_id>
/admin/dashboard/jobs/new?entity_type=organization&entity_id=<organization_id>
/admin/dashboard/jobs/new?entity_type=artist&entity_id=<artist_id>
```

Legacy venue context also works if Phase 6 helpers are installed:

```txt
/admin/dashboard/jobs/new?venue_id=<venue_id>
```

## Data written

`JobPostingBuilder` submits a payload containing:

```txt
employer_entity_type
employer_entity_id
venue_id when the employer is a venue or scoped to a venue
title
description
department
position
employment_type
location
role_type
number_of_positions
salary_range
requirements
responsibilities
benefits
skills
experience_level
remote
urgent
required_certifications
application_form_template.fields[]
onboarding_template_id
status
```

The actual database insert should still happen inside `HiringOnboardingService.createJobPosting()`.

## Validation rules

- Title, description, department, and position are required.
- `number_of_positions` must be between 1 and 1000.
- Salary max cannot be lower than salary min.
- Application fields require a `name`, `label`, valid `type`, and `order`.
- Select and multi-select fields require at least one option.
