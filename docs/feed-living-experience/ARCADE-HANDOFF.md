## Gameplay contracts

**Rhythm game**
- Controls: D/F/J/K and buttons, pause/resume/reset, BPM clamped 65–200. Difficulty options: Easy (every other beat), Normal (quarter beats), Hard (eighth beats). Calibration shifts chart presentation ±150ms but does not change the audio or its licensing.
- Perfect `|delta| <= 75ms`, good `<= 170ms`, miss otherwise.
- Misses clear combo; accurate notes increase combo and score.
- Practice has synthesized pulse; creator tracks stream at authorized full/preview access.
- Visible notes are scheduled relative to audio.currentTime (or practice elapsed time). Generated note pattern follows selected BPM; it is not measured from the track. Clip end finishes gameplay.
- Personal best score persists **only in this browser's localStorage**, per track + difficulty. No server-side leaderboard, anti-cheat, account-linked score, or gameplay uploads in this slice. Records can be cleared by the browser.

**DJ platformer**
- Original level width 3,220 game pixels, scrolling camera, 15 records, 9-record entrance requirement.
- Arrow/A-D move, Up/W/Space jump, dedicated mobile pointer controls. Escape pauses when game is focused.
- 3 lives; fall or collision costs a life. Stomping an enemy clears it. Checkpoints keep collected records.
- Runs in browser canvas via requestAnimationFrame, frame-time clamp. Stops simulation on pause/tab hidden and skips expensive canvas redraws while static.
- Sound effects are generated only after explicit user interaction and can be muted.
- On completion, awards a bounded, local run score based on vinyls, surviving lives, defeated enemies, and time; saves a **device-only** best. Multiple levels, verified server scores, boss battles, multiplayer, and customizable DJ avatars are future phases.

## CRITICAL: artist opt-in before fan-wide songs

Streaming/upload rights and permission to synchronize music to interactive games are **not the same grant**. Until content legal review, public track gameplay must not automatically include every rights-confirmed Tourify song. The current API is owner-practice-only, intentionally.

**Next development milestone (required before enabling general users' song selection):**
1. Product/legal defines opt-in licensing terms covering masters **and compositions**, territories, permitted game uses, snippets, promotion, monetization, retention, withdrawal effects, credits, royalty allocations and contributor rights.
2. Add an additive `music_arcade_permissions` record keyed by `artist_music.id`, granted by verified track owner (and rights authority), consent version, rights assertion, scope, grant/revoke timestamps and audit trail. Do not treat a client-provided userId as authorization.
3. Artist dashboard control "Allow this track in Tourify Arcade" with informed, revocable consent. Existing uploads are OFF by default. Verify track ownership server-side and preserve RLS.
4. Add a server catalog query returning only opted-in, approved, visible tracks. Existing per-listener entitlement and preview restrictions still apply. A preauthorized catalog entry must never replace stream-access checks.
5. Obtain rights-approved beatmaps or process waveform tempo metadata using a **permitted** offline worker that does not distribute raw audio or bypass playback restrictions. Add measured BPM, audio offset, difficulty chart version, quality validation and moderation.
6. Add artist credit, direct profile/track link, play analytics labeled `source=arcade_rhythm` and revocation that immediately hides unlicensed tracks from new sessions.
7. Audit consent/access with Supabase RLS tests, fan/creator account permutations, paid track previews and revoked tracks.

## Beat Deck keyboard-input fix — real-player feedback (2026-10-18)

### Root cause from code review
- The original global `keydown` listener returned immediately unless the active DOM element was inside `sectionRef`. Playing while focus moved outside the section therefore silently ignored D/F/J/K.
- The existing game acknowledged only scored presses and usually showed just `Keep watching the beat line` when a press was not in the hittable note window. Neither the on-canvas receptor nor pad visibly changed when a key was pressed.
- A 171ms selection window did not match the 170ms `good` scoring cutoff; boundary hits could count points despite being evaluated as `miss`.

### Implemented change
- Keyboard mapping is centralized in `lib/arcade/rhythm-input.ts`, matching D/F/J/K case-insensitively with physical `KeyD/KeyF/KeyJ/KeyK` fallback; modifiers/composition are rejected.
- During an **active** game, keyboard hits are processed irrespective of game-section focus. Inputs, selects, textareas, content-editable regions and rich text editors keep their normal typing behavior. Keyboard repeat is suppressed for scoring.
- Keydown marks its lane pressed; keyup clears it. Release is also performed on window blur, reset and pause. Touch pointer capture handles release outside the button. A keyboard-activated pad click is accessible with Enter/Space and does not duplicate a pointer hit.
- Both the canvas hit receptors and visible D/F/J/K pads show pressed/flash feedback, whether or not a note is scored. A keyboard-active status and the **last recognized key** are shown below the note highway.
- On unscored input, feedback explicitly states `<KEY> REGISTERED · too early / too late / no note waiting`. A judged hit clearly reports the key + Perfect/Nice.
- `findHittableNote` and `judgeTiming` now share one 170ms hit window.
- Unit regression coverage in `__tests__/arcade/rhythm-input.test.ts` is wired to Arcade CI.

### Manual verification still required
1. Start a practice round and press D, F, J and K with focus on the main body, canvas, the pads, and non-input controls. Each must show a press even when no note matches; verify pressing before Start does not score.
2. Focus an editable text field or selector and type D/F/J/K: inputs should retain keystrokes and the game should not intercept the values.
3. Hold one key: exactly one note should be judged until the key is released, while the pad remains lit; release makes it unpressed. Repeat with multiple held keys.
4. Test touch press/drag off/release, rapidly alternating taps, keyboard-activated pad buttons, pause/reset mid-hold, tab switch and browser blur; no stuck lanes or duplicate hits.
5. Test near-threshold accurate/early/late hits, including calibrated ±150ms audio offset; check device audio latency separately.
6. Verify desktop Chrome, Firefox, Safari, and Chrome/Safari mobile with slow hardware and screen reader; no screen-width overflow or flashing issues.
7. Reminder: chart remains a tempo-based practice pattern, **not** a verified beatmap derived from uploaded audio.

Status: changes committed to draft branch, **browser gameplay verification required before merging**.
