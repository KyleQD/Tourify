- `/arcade`: arcade landing hub with original game cards.
- `/arcade/beat-deck`: "Beat Deck", an original four-lane note highway with D/F/J/K keyboard input and four touch pads; hit/miss windows, combo, score, device-local personal best, pause, reset, tempo selection, Easy/Normal/Hard difficulty, audio calibration (±150ms), note animations. Browser-synthesized practice beat available without a Tourify account.
- `/arcade/dj-quest`: "DJ Odyssey: Road to Studio 54", original pixel/vector side-scroller, scrolling club-city setting, DJ sprite, record pickups, three themed enemy types (bouncer, loudspeaker, disco-ghost), stomp-to-defeat, pit hazards, checkpoints, lives, sound FX, touch controls, keyboard controls, Studio 54 destination requiring 9 vinyl records.
- `/dashboard`: new Arcade teaser routes into both games.
- `/api/arcade/tracks`: returns **only the authenticated creator's own published, visible, approved, rights-confirmed artist_music tracks** (creator practice, no fan-wide game synchronization).
- Audio playback is requested from existing `/api/music/stream?source=arcade&trackId=...` which calls `resolveMusicAccess` and returns a signed, temporary URL. Arcade issues are now limited to **300 seconds, no-store**; standard music player remains at 3,600 seconds. These are short-lived bearer links, **not DRM**, and they can still be saved while valid.
- Rhythm notes are **deterministic tempo-adjustable practice charts**, NOT automatic audio transcription or author-approved beatmaps. User can set the rough tempo. Do not market automatic beat matching as complete.
- Original game visuals/audio generated by browser code; **no Guitar Hero or Mario artwork, levels, music or protected branding** used. "Studio 54" is a requested thematic club destination; no official affiliation or licensed Studio 54 visual identity claimed.

**Flow File (.flow) format and protected audio:** separate workstream; see [Flow File handoff](../flow-file/FLOW-FILE-HANDOFF.md), [foundation](TPA-FOUNDATION.md) and [Arcade rights SQL proposal](TPA-ARCADE-RIGHTS-PROPOSED.sql). The second file is not an applied migration. No Flow File parser/encoder, segmented DRM service, watermarking or verified beatmap pipeline is claimed to be shipped.

## Gameplay contracts

**Rhythm game**
- Controls: D/F/J/K and buttons, pause/resume/reset, BPM clamped 65–200. Difficulty options: Easy (every other beat), Normal (quarter beats), Hard (eighth beats). Calibration shifts chart presentation ±150ms but does not change the audio or its licensing.
- Perfect `|delta| <= 75ms`, good `<= 170ms`, miss otherwise.
- Misses clear combo; accurate notes increase combo and score.
- Practice has synthesized pulse; creator tracks stream at authorized full/preview access.
- Visible notes are scheduled relative to audio.currentTime (or practice elapsed time). Generated note pattern follows selected BPM; it is not measured from the track. Clip end finishes gameplay.
- Personal best score persists **only in this browser's localStorage**, per track + difficulty. No server-side leaderboard, anti-cheat, account-linked score, or gameplay uploads in this slice. Records can be cleared by the browser.

**DJ platformer**
- Original level width 3,220 game pixels, scrolling camera, 15 records, 9-record entrance requirement.
- Arrow/A-D move, Up/W/Space jump, dedicated mobile pointer controls. Escape pauses when game is focused.
- 3 lives; fall or collision costs a life. Stomping an enemy clears it. Checkpoints keep collected records.
- Runs in browser canvas via requestAnimationFrame, frame-time clamp. Stops simulation on pause/tab hidden and skips expensive canvas redraws while static.
- Sound effects are generated only after explicit user interaction and can be muted.
- On completion, awards a bounded, local run score based on vinyls, surviving lives, defeated enemies, and time; saves a **device-only** best. Multiple levels, verified server scores, boss battles, multiplayer, and customizable DJ avatars are future phases.

## CRITICAL: artist opt-in before fan-wide songs

Streaming/upload rights and permission to synchronize music to interactive games are **not the same grant**. Until content legal review, public track gameplay must not automatically include every rights-confirmed Tourify song. The current API is owner-practice-only, intentionally.

**Next development milestone (required before enabling general users' song selection):**
1. Product/legal defines opt-in licensing terms covering masters **and compositions**, territories, permitted game uses, snippets, promotion, monetization, retention, withdrawal effects, credits, royalty allocations and contributor rights.
2. Add an additive `music_arcade_permissions` record keyed by `artist_music.id`, granted by verified track owner (and rights authority), consent version, rights assertion, scope, grant/revoke timestamps and audit trail. Do not treat a client-provided userId as authorization.
3. Artist dashboard control "Allow this track in Tourify Arcade" with informed, revocable consent. Existing uploads are OFF by default. Verify track ownership server-side and preserve RLS.
4. Add a server catalog query returning only opted-in, approved, visible tracks. Existing per-listener entitlement and preview restrictions still apply. A preauthorized catalog entry must never replace stream-access checks.
5. Obtain rights-approved beatmaps or process waveform tempo metadata using a **permitted** offline worker that does not distribute raw audio or bypass playback restrictions. Add measured BPM, audio offset, difficulty chart version, quality validation and moderation.
6. Add artist credit, direct profile/track link, play analytics labeled `source=arcade_rhythm` and revocation that immediately hides unlicensed tracks from new sessions.
7. Audit consent/access with Supabase RLS tests, fan/creator account permutations, paid track previews and revoked tracks.

## QA — required before production

- `npx vitest run __tests__/arcade` and relevant feed tests. CI workflow at `.github/workflows/arcade-unit-tests.yml` runs four targeted suites, including the creator-track route authorization test. Until the repo lockfile is repaired, its **temporary** `npm install --legacy-peer-deps --package-lock=false --ignore-scripts` avoids mutating the committed dependency lock; this is not a durable reproducible solution.
- `npm run typecheck`; clean Next build (including `/arcade/*`).
- Keyboard focus: D/F/J/K should work **only** while rhythm game is active; arrows/space **only** while DJ game is active. No page scroll lock when game isn't focused.
- Mobile: tap lane buttons rapidly, hold left/right, release pointer outside, simultaneous move+jump, rotate screen, test small phones and touch target sizes.
- Runtime: pause/resume both games; tab switch; retry denied/expired stream; unmount cleans audio/RAF; creator-track list empty/errored; browser audio blocked; preview clips shorter than metadata.
- Platformer: jump gap, stomp bouncer, fall, checkpoint respawn, win with exactly nine records, locked door with eight, gameover after three collisions, restart.
- Security: no unauthorized track leakage; no signed stream URL persisted; no grants implied by public streaming alone; no copyrighted game artwork.
- Dependency triage: GitHub CI exposed two pre-existing package issues: root `package-lock.json` is out of sync (`npm ci` EUSAGE, numerous missing packages), and the Mobile CI root install hits `date-fns@3` versus `@base-ui/react` optional peer `date-fns@4` (ERESOLVE). Correct these in a separate reviewed dependency reconciliation (not an unreviewed install-force change). An inspected Vercel preview install log reported **72 npm advisories (including 2 critical)** in the existing dependency tree. This is a report from package audit, not proof those packages are exploitable at runtime. Track a separate reviewed remediation; do not use an unreviewed `npm audit fix --force` in this feature PR.
- Accessibility: headings, focus styles, named controls, non-color-only lane identity, status updates, reduced-motion accommodations; canvas needs alternative textual gameplay description.

## Gameplay expansion — 2026-10-18

### Implemented on this draft branch (needs in-browser QA)
- **Beat Deck concert director:** Three selectable original 2D venues (Underground Club, Festival Main Stage, Neon Skyline), parallax-like skyline/stage geometry, colored light beams, a crowd silhouette, and combo-based energy tiers from Soundcheck to Encore Mode. Venue swaps do not reset or modify the note chart, streaming entitlement, scoring, or audio offset.
- **Accessibility:** Stage lighting has an explicit "Calm stage lighting" control initialized from `prefers-reduced-motion`; high-energy flashes and beam movement are reduced in that mode. Full WCAG motion/contrast testing remains pending.
- **DJ Odyssey movement:** Adds a 120ms post-ledge coyote window and a 150ms pre-landing jump buffer. Jump requires a fresh button/key press; death/reset clears queued inputs to avoid auto-jumping. Existing path and physics constants remain otherwise intact.
- **DJ Odyssey club-city route:** The existing first level is now visually divided into Record Row, Subway Beats and Disco Mile, with ambient color changes, marquees, contextual district announcements and a route progress bar. These are **districts within ONE continuous level**, not three newly authored levels.
- **Enemy collision fix:** Taking damage/respawning aborts the collision frame so a simultaneous accidental portal victory cannot occur.
- **Studio 54 interactive victory:** A successful finish unlocks a lightweight original-synth `DJBoothFinale`: Deck A/B looping practice notes, scratch buttons, 0–100 equal-power crossfader, stop control, accessibility labels, and automatic audio cleanup on unmount. It uses **only locally synthesized notes**; no uploaded music, samples, rights grants, or `.flow` content.
- **Arcade hub:** Now describes the stage choices, districts, movement assist and playable finale.
- **Logic tests:** `__tests__/arcade/stage-director.test.ts`, `__tests__/arcade/dj-mixer.test.ts`, expanded `__tests__/arcade/dj-quest-level.test.ts`; Arcade CI workflow targets these along with existing gameplay/stream tests.

### Exact limitations
- Beat Deck's creator-track note charts are still deterministic BPM practice maps, **not** derived from real audio transients. The stage lighting pulses to the chosen practice BPM and current score; it is not a live audio analyzer. Authenticated owner-only track catalog remains unchanged.
- DJ finale is a simple click-driven, original Web Audio synth sequencer, not true stem mixing or performance-grade beat scheduling; no claims of real artist-sample support.
- DJ district art is procedurally drawn in canvas using the existing single-level scene, without newly licensed images.
- Device-local scores are not verified or associated with signed-in leaderboard identities.
- `.flow` development stays in [separate handoff](../flow-file/FLOW-FILE-HANDOFF.md).
- **Do not merge based on unit tests alone.** Full desktop/mobile/browser gameplay QA and integrated build verification are release gates.
