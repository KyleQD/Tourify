# WORK-P01 — Work Mode Read Model and Work Hub Reconciliation

## Objective

Reconcile the mature Work behaviors from the verified reference build into the current codebase without creating parallel assignment, task, messaging, schedule, or attendance systems.

## Entry gate

## Canonical task source

## Phase-specific decisions

- Keep Work Mode as a transient operational context.
- Keep `employment_assignments` as the post-hire assignment anchor unless P00 establishes a verified replacement.
- Prefer a server-authorized Work read model if P00 confirms a safe integration path.
- Reconcile shared Work types before composing the richer dashboard.
- Preserve useful reference task semantics (`acknowledge`, `start`, `complete`, `block`) while adapting them to the current canonical task backend.
- Worker attendance/check-in state must not be fabricated by offline/local-only writes.
- Existing messaging, publications, shifts, tours/events, documents, jobs, notifications, and staffing services should be adapted rather than recreated.
