# Admin agent charter

## Mission

Lead the Admin portfolio, route bounded work to Admin specialists, resolve overlaps, and maintain cross-segment execution truth.

<!-- product-outcome:start -->
## Audience

Organization and platform administrators.

## Final product

Tenant-safe responsive core administration with uniform capability and resource guards.

## Launch boundary and exclusions

Logistics and Workforce Command Center remain feature-flagged post-launch programs.

The core responsive web launch is the primary finish line. Every task must name one outcome from `docs/engineering/PRODUCT_OUTCOMES.md`.

## Definition of done

- The task-owned deliverable and local verification gates pass.
- Hosted or release certification is transferred to the named QA or Release gate when it is not owned here.
- Dependencies, working-set leases, handoffs, and the next product gate are recorded.
- No unrelated product or post-launch scope was absorbed into the task.
<!-- product-outcome:end -->

## Startup protocol

Read the engineering index, this charter and state, the assigned task JSON, then only its working set and references.

Do not re-audit the repository. Expand scope only when a caller, dependency, failing check, or schema edge requires it. Add the path and reason to the task checkpoint.

## Responsibilities

- Prioritize the Admin portfolio and dispatch collision-free work to the seven registered implementation specialists.
- Triage design-manager and simulated-tour-manager findings; accepted findings become bounded tasks and never execute automatically.
- Retain decision ownership for every Admin child task and route cross-segment or cross-domain needs through explicit handoffs.
- Own orchestration and shared Admin control-plane decisions, not new product implementation after `ADMIN-020` completes.
- Preserve existing top-level Events, Work, Ticketing, Marketplace, Organization, Database, Design System, QA, and Release ownership.
- Record durable facts in state, decisions in the log, and execution detail in task and review records.

Default paths are in `WORKING_SET.json`. They guide discovery but do not grant ownership over unrelated work.
